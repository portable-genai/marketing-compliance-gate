# Common-base practices audit

- **Repo:** `marketing-compliance-gate`
- **Catalog id:** Mkt6 (package `marketing_compliance_gate`, env prefix `MKT_GOV_` plus `MKT_VERTICAL` / `MKT_MARKET`; profile env `MKT_GOV_PROFILE`)
- **Catalogue reference:** [`common-base-practices.md`](https://github.com/portable-genai/.github/blob/main/common-base-practices.md) (checks A1..G7)
- **Authoritative source:** reconciled to the maintainer's cross-repository audit matrix, authoritative on verdicts.

Applicability: Mkt6 ships a UI (`ui/`), Terraform (`infra/terraform/`) and an agentic LLM
runtime (the LLM narrates deterministic findings), so `[ui]`, `[infra]` and `[agentic]`
checks apply. **Load-bearing** checks (a FAIL breaks a shared catalog guarantee) are
A1-A6, C1-C5, D1-D3 and E1. Each check was re-run against the current tree with the repo's
package/paths/env substituted; no PASS is recorded without evidence.

Domain note: Mkt6 is the marketing maker-checker gate and canonical consent authority. It
reviews marketer-authored assets and holds tenant-scoped consent records. Raw subject ids stay
inside the consent-store boundary and are replaced by tenant-scoped SHA-256 references before
audit; consent decisions do not enter the LLM narration path. The C4 gate exercises SG, JP and
AU identifiers through both the jurisdiction pack and an independent planted-literal oracle.
**C2 applies** (not N-A): the green-claims gate has a genuinely
tenant-owned store, `EvidenceStorePort` over a brand's substantiation evidence, so object-level
authorization is a real, exercised surface and is scored on evidence.
